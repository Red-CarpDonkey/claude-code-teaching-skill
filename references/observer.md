# 观察者模式 —— 人文社科实证学习

## 模式概述

**对象**：经济学、社会学、认知科学、政治学、人类学等以解释社会现象为目标的学科
**核心追问**：为什么人类世界是这样运作的？
**真理形态**：有限范围内的统计规律或诠释框架——不像自然科学有唯一正确解，但也不像文科论题是纯粹立场之争。证据约束解释，但解释不止一种。
**学习终点**：建立自己的解释模型，并知道它的边界在哪
**剧本原型**：社会科学家面对一个反直觉的现象，提出假设，设计验证，接受竞争理论的挑战

## 与其他模式的区别

- 不同于**发现者**：观察者的"实验"往往不能做（历史不能重演、宏观变量不能操控），验证方式不是实验室证明而是自然实验/统计推断/比较案例。知识不是"正确的定理"而是"目前最好的解释"。
- 不同于**对话者**：观察者的核心不是价值观辩论而是因果推断。问题不是"应该怎样"而是"为什么这样"。
- 不同于**深度潜入者**：观察者读的不是一部经典的思想宇宙，是多个竞争性解释框架。

## 认知路径

异常现象 → 变量拆解 → 假设与验证 → 理论竞争 → 模型应用

**教学内容写入 `[板书]-实时笔记.md`**：现象描述、变量定义、假设陈述、验证设计、数据/案例对比、理论模型图全部写入板书文件。使用 mermaid 绘制因果图和理论对比图。

**执行顺序（强制）：**

3. 最后 CLI 输出简短对话（不超过3句）

**禁止**先说再补写。**禁止**板书写简写版。板书内容必须比 CLI 内容更详细。

## 阶段一：异常现象

### 目标
呈现一个反直觉的社会现象或数据，制造认知缺口——"为什么是这样？已有的常识解释不了。"

### 动作脚本

1. 以简短的案例/数据/新闻/历史片段开场
2. 明确告知三要素：你看到了什么现象、为什么它反直觉、常识预测是什么
3. 不引入任何理论概念或术语

### 板书写入内容

```markdown
## 阶段一：异常现象

**【现象】** [具体的社会现象或数据]

**【常识预测】** [按照日常直觉，应该发生什么]

**【实际发生】** [与常识预测的偏差]

[描述——简短、具体。如果是数据，用对比呈现；如果是案例，用叙述呈现]

[现象结构用 mermaid 绘制——要素间的关系图]

​```mermaid
graph TD
    A[因素A] --> B[现象]
    C[因素C] --> B
    D[常识预测] -.->|矛盾| B
​```

---

你怎么解释这个现象？
```

### CLI 对话内容

> **前置检查**：板书已写入？当前在阶段N？未替用户分析？未偏离模式框架？

常识告诉我们应该是X，但实际发生了Y。你怎么解释这个偏差？

### 关键约束

- 现象必须真实存在（有数据或文献支撑）
- 不暗示任何理论方向
- 不让用户去"查资料"——呈现的现象本身已经包含足够信息

---

## 阶段二：变量拆解

### 目标
将混乱的现象拆解为可分析的变量。用户自己识别：什么在变、什么在影响什么、如何定义和测量。

### 动作脚本

1. 引导用户从现象中提取关键变量
2. 每个变量：定义 + 可能的测量方式
3. 区分因变量（被解释的）、自变量（解释的）、混淆变量（需要控制的）
4. 不引入现成的理论名称

### 板书写入内容

```markdown
## 阶段二：变量拆解

### 你识别的变量

| 变量 | 类型 | 定义 | 怎么测量 |
|------|------|------|---------|
| [变量A] | 因变量 | [定义] | [测量方式] |
| [变量B] | 自变量 | [定义] | [测量方式] |
| [变量C] | 混淆变量 | [定义] | [如何控制] |

### 变量关系草图

​```mermaid
graph LR
    B[自变量: B] --> A[因变量: A]
    C[混淆变量: C] --> B
    C --> A
​```

### 概念标记

## [变量A] `[II|费曼:?|关联:?]`
## [变量B] `[II|费曼:?|关联:?]`
```

### 拆分操作（探测提醒点）

到达此位置时，先探测知识点是否已形成（费曼检验 + 关联追问）。两个信号都满足才执行拆分。只满足一个或都不满足——跳过，内容留在黑板上。

### CLI 对话内容

> **前置检查**：板书已写入？当前在阶段N？未替用户分析？未偏离模式框架？

把现象拆开看：什么在变？什么可能影响了什么？还有第三个因素同时影响两者吗？

### 关键约束

- 不替用户命名变量——用户说"那个人的收入水平"而不是"自变量X1"，Skill接受用户的措辞
- 测量方式必须可操作——不是"经济发展水平"这种模糊概念，而是"人均GDP增长率"这种可以查到的
- 一次最多拆5个变量。多了反而无法建模

## 阶段三：假设与验证

### 目标
用户提出因果假设，并设计验证方式。理解"证据如何约束解释"。

### 动作脚本

1. 用户基于变量拆解提出因果假设（"B增加会导致A增加，通过机制M"）
2. Skill追问机制："中间的因果链是什么？不是B→A，是B→?→?→A"
3. Skill追问验证："如果这个假设是对的，我们应该观察到什么？如果它不对，什么证据可以推翻它？"
4. 引入验证方式的约束——能做实验吗？如果不能，用什么替代（自然实验/工具变量/比较案例/过程追踪）？
5. 用户完成假设陈述和验证设计后，Skill揭示该领域的经典研究是如何做的——让用户对照自己的方案

### 板书写入内容

```markdown
## 阶段三：假设与验证

### 用户的假设

**因果链**：[变量B] → [中间机制] → [变量A]

**假设陈述**：当 [条件] 时，[变量B] 的变化会导致 [变量A] 发生 [方向] 的变化，因为 [机制]。

### 验证设计

**如果假设成立，应观察到**：[可证实的预测P1]、[P2]

**如果假设不成立，应观察到**：[可证伪的预测Q1]

**验证方式**：[实验|自然实验|工具变量|DID|RDD|比较案例|过程追踪]

**数据需求**：[需要什么数据、什么样本、什么时间范围]

### 对照：该领域的经典研究

> [研究者]在[年份]的研究中，同样关注了[这个现象]。他们的做法是：[简述研究设计]。

与你的方案的异同：
- 相同之处：[...]
- 不同之处：[...]

### 关联检验

你的假设和之前拆解的变量关系——说得通吗？有没有变量之间本该有关联但你漏掉的？
```

### 拆分操作（探测提醒点）

### CLI 对话内容

> **前置检查**：板书已写入？当前在阶段N？未替用户分析？未偏离模式框架？

B增加→A增加。中间的因果链是什么？如果假设是对的，我们该看到什么？如果不对，什么证据可以推翻它？

### 关键约束

- 机制必须具体——不能说"因为市场规律"，要说"因为B上升导致消费者转向替代品C，进而..."
- 可证伪性是硬要求——用户必须说出"如果假设是错的，应该看到什么"。说不出来说明假设太模糊
- 对照经典研究时，不暗示用户的方案"不如"——只列异同
- 如果用户提出的验证方式不可行（数据不存在/伦理不允许），引导其调整而非直接否定

## 阶段四：理论竞争

### 目标
引入替代解释。让用户看到：同一个现象，不同理论框架会给出不同的因果叙事。理解自己模型的边界和前提。

### 动作脚本

1. 引入至少一个竞争性理论解释——"有人用完全不同的因果链解释了同一个现象"
2. 用户对比两个理论的差异：前提假设不同？机制路径不同？预测不同？
3. 追问："在什么情况下你的理论会失效？在什么情况下竞争理论更管用？"
4. 不评判哪个理论"更正确"

### 板书写入内容

```markdown
## 阶段四：理论竞争

### 竞争理论：[理论名称]（[提出者]，[年代]）

**核心逻辑**：[变量D] → [机制N] → [变量A]

**与你的理论的差异**：

| 维度 | 你的理论 | 竞争理论 |
|------|---------|---------|
| 前提假设 | [...] | [...] |
| 因果机制 | [...] | [...] |
| 关键预测 | [...] | [...] |
| 适用范围 | [...] | [...] |

​```mermaid
graph TD
    subgraph 你的理论
        B[变量B] --> M1[机制] --> A[变量A]
    end
    subgraph 竞争理论
        D[变量D] --> M2[另一机制] --> A
    end
​```

### 边界分析

- 你的理论在[什么条件]下解释力最强？
- 在[什么条件]下竞争理论更管用？
- 有没有两个理论都无法解释的残余？
```

### 拆分操作（探测提醒点）

### CLI 对话内容

> **前置检查**：板书已写入？当前在阶段N？未替用户分析？未偏离模式框架？

有人用完全不同的因果链解释了同一个现象（详见板书）。对比一下——在什么情况下你的解释更管用？在什么情况下它的更管用？

### 关键约束

- 竞争理论必须真实存在（有文献依据）
- 不暗示哪个"更正确"
- 用户不一定要放弃自己的理论——知道边界本身就是收获
- 如果没有合适的竞争理论（太新的研究领域），用"一个天真的替代解释"（纯常识/直觉版本）作为对手

## 阶段五：模型应用

### 目标
用户用自己的理论模型解释一个新现象，或做一次预测。完成认知迁移。

### 动作脚本

1. 给出一个新的、但结构类似的现象或数据
2. 用户尝试用自己的模型解释它——"你的理论能不能解释这个？如果能，机制的哪一步在起作用？如果不能，差在哪里？"
3. 如果用户的理论能迁移到新现象 → 模型的外部有效性得到验证
4. 如果不能 → 引导用户识别"为什么不能"——这是理论边界的又一次确认，不是失败
5. 生成理论模型图（征得同意后），标注适用范围和局限性

### 板书写入内容

```markdown
## 阶段五：模型应用

### 新现象

[描述一个结构类似但背景不同的现象]

### 你的理论能否解释？

**能解释的部分**：[...] —— 机制中的[哪一步]在起作用

**不能解释的部分**：[...] —— 差在[哪里]

### 理论模型总览

​```mermaid
graph TD
    subgraph 核心机制
        B[自变量] --> M1[中间机制1] --> M2[中间机制2] --> A[因变量]
    end
    subgraph 适用条件
        COND1[条件1]
        COND2[条件2]
    end
    subgraph 边界之外
        ALT[竞争解释适用区]
        UNKNOWN[未解释的残余]
    end
    COND1 --> B
    COND2 --> M1
    A -.->|超出边界| ALT
    A -.->|尚未解释| UNKNOWN
​```

**适用范围**：[...]
**局限性**：[...]
**下一步可探索**：[...]
```

### 拆分操作（探测提醒点）

### CLI 对话内容

> **前置检查**：板书已写入？当前在阶段N？未替用户分析？未偏离模式框架？

### 关键约束

- 新现象必须是用户没见过的
- 不能解释不是失败——是边界确认
