## 文件名规范

- `[板书]-实时笔记.md`：当前会话的黑板文件。每次回复追加内容。分支点触发时，相关内容被剪切为知识卡片，原位置替换为链接。
- `[知识点]-[名称].md`：独立知识卡片。名称用简短的英文或中文概括该知识点。
- `[主题名]/`：学习主题的子文件夹，在首次启动时根据用户输入的主题名自动创建。

## 双向链接 frontmatter

每张知识卡片必须包含以下 frontmatter：

```yaml
---
tags: [模式, 主题, 子话题]
difficulty: 初|中|高
mode: [discoverer|engineer|dialoguer|deep_diver]
previous: "[[上一个知识点]]"
next: null
branch_of: "[[主题名]]"
created_at: "2026-06-03T12:00:00"
---
```

- `previous`：拆分生成时自动指向上一个已拆分的卡片，形成学习链
- `next`：下一张卡片生成时回填，`null` 表示当前链尾
- `branch_of`：指向主题总览页或索引

## 板书文件拆分标记

在 `[板书]-实时笔记.md` 中，已被拆分为卡片的内容替换为：

```markdown
→ 已拆分：[[知识点-名称]]
```

## 知识点卡片模板（通用，四种模式共用）

一张卡片记录一个知识点——认知网络中的一个节点。卡片的核心是用户自己的话，Skill 只做格式化。元阶段决定形态，四个条件决定字段。

```markdown
---
tags: [模式标签]
mode: [discoverer|engineer|dialoguer|deep_diver]
meta_stage: [II|III|IV|V]
feynman_passed: true
connection_expressed: true
previous: "[[上一个知识点]]"
next: null
branch_of: "[[主题名]]"
created_at: "2026-06-08T..."
---

# [用户措辞提取的标题]

## 用户的一句话

> [费曼检验产出——用户原话，不做润色]

## 关联边

→ [[已知概念A]]（[因果|对比|层级|类比]）
→ [[已知概念B]]（[因果|对比|层级|类比]）

## 调用证据

[用户在什么场景下自己用了它——可以是推导中的一个判断、代码中的一次正确使用、辩论中的一个论证回合、素读后的一次自主阐释]
```

### 按元阶段的补充段

每个元阶段只填对应段，其余删除。不要一张卡片塞多个元阶段的内容。

**元阶段 II（概念）——补充段：**

```markdown
## 概念边界

- 是什么：[一句话定义]
- 不是什么：[常见混淆]
- 包含的要素：[拆解出的基本单元]
```

**元阶段 III（机制）——补充段：**

```markdown
## 推导/机制

[用户自己完成的推导链或因果路径——关键步骤是用户自己填的，Skill只搭了脚手架]

**用户踩过的坑**：[推导中暴露的错误 + 怎么纠正的]
```

**元阶段 IV（边界）——补充段：**

```markdown
## 局限与替代

- 适用条件：[什么情况下有效]
- 失效条件：[什么情况下不适用]
- 替代路径：[历史上存在/用户考虑过的其他方案] — [为什么没选]
```

**元阶段 V（连接）——补充段：**

```markdown
## 跨领域映射

- [[学科A的某概念]]：[类比关系]
- 用户的应用/创作：[用户自己的迁移产物]
```

### 按模式的补充段（可选）

**发现者模式追加：**

```markdown
## 对照原文

> [历史论文/定理的原文引用]

与你的推导对比：[一致之处 | 不同路径]
```

**工程师模式追加：**

```markdown
## 代码评审关键点

[四维诊断中用户自己意识到的改进——不是Skill的四条全列，是用户评审后自己说出的]
```

**对话者模式追加：**

```markdown
## 论证演变

初始立场 → [辩论中转折] → 当前立场
```

**深度潜入者模式追加：**

```markdown
## 文本与我

[用户将文本与自身生命经验关联的自述]
```

### 模板使用规则

1. **标题**从费曼检验中用户的一句话提取。Skill不命名。
2. **用户的一句话**是原话引用，不做润色。哪怕表达不精确——精确是后续卡片迭代的事。
3. **关联边**至少一条。零条关联的不叫知识点，不生成卡片。
4. **调用证据**具体到时点场景——不是"用户理解了什么"，是"用户在什么情况下用了它"。
5. **补充段**只填当前元阶段对应的那一段。元阶段II的卡片不包含推导（那是III才有的），元阶段III的卡片不包含跨领域映射（那是V才有的）。没推到那个深度就不填。
6. 四个条件（独立可陈述、可被调用、有关联边、用户自己说的）在 frontmatter 中由 `feynman_passed: true` 和 `connection_expressed: true` 以及正文中的"用户的一句话"和"调用证据"四个字段共同满足。

## 疑问卡片模板

用户每次临时提问，按提问中断协议（`references/question-protocol.md`）分类处理后，工程师模式生成 `[疑问]-[简短标题].md`，其他模式将模板内容附加到 `.study/questions.md`。

```markdown
---
tags: [疑问, 模式标签]
mode: [discoverer|engineer|dialoguer|deep_diver]
question_type: [不理解|前探|偏离|痛点提前]
related_knowledge: "[[关联知识点]]"
raised_at: "[元阶段] [阶段名]"
resolved_at: null
status: [open|deferred|resolved]
created_at: "2026-06-08T..."
---

# [疑问简短标题]

## 原始问题

> [用户原话]

## 上下文

- 当时在学：[主题/概念]
- 当时在：[元阶段X，阶段Y]
- 前一条板书内容：[摘要]

## 处理

- 类型：[A/B/C/D]
- 处理方式：[当场回答 | 暂缓到[目标阶段] | 简短答后回主线]
- Skill 的回应：[摘要]

## 答案

[当场回答的内容记录在此；暂缓的等回访时补上。此字段为空等于未完成]

## 关联

- 触发的知识点：[[知识点-xxx]]
- 暴露的认知缺口：[如果有，指出哪个概念的哪个维度用户还没理解]
```

**硬约束：**

- `related_knowledge` 至少关联一个已有知识点。若无关联，说明这个疑问不在认知网络里——可能是偏离型问题（C类），标记为 `status: open` 后回到主线，不强求关联
- `答案` 字段不能为空（`deferred` 状态除外）。空答案 = 未完成，content-reviewer 检测到空答案且 status 为 `resolved` → FAIL
- `question_type` 和 `raised_at` 在创建时写入，`resolved_at` 和 `status` 在问题关闭时更新
