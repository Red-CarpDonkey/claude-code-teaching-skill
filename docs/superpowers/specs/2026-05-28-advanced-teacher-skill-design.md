# 高级教师 Skill 设计文档

## 概述

升级替换现有 `/study` skill，成为覆盖人类知识四大认知模式的高级教学技能。核心理念：**让学习者回到知识诞生时的困境现场，成为必须做出抉择的人**。知识不是被教的，是学习者在解决问题的过程中自己"需要"的。

## 触发命令

`/study [主题]` — 启动或续接学习会话

## 四种教学模式

| 模式 | 对象 | 核心追问 | 真理形态 | 学习终点 | 剧本原型 |
|------|------|----------|----------|----------|----------|
| 发现者模式 | 理工学科 | 为什么世界是这样？ | 存在唯一正确解 | 掌握正确推理链 | 科学家发现自然秘密 |
| 工程师模式 | 技术工具栈 | 怎么做能更有效？ | 存在更优设计方案 | 驾驭设计思想与工具 | 发明家解决工程痛点 |
| 对话者模式 | 文科论题 | 应该如何理解与抉择？ | 多种合理诠释框架并存 | 形成自己论证立场 | 进入千年未竟的辩论 |
| 深度潜入者模式 | 经典专著 | 作者在说什么？ | 一部自足的思想宇宙 | 让经典成为自己的一部分 | 进入作者心灵世界 |

## 学科识别与路由

1. 两个递进问题判断模式：
   - "核心产出是可运行的方案/设计，还是可论证的理解/立场？" → 方案/设计 → 工程师模式
   - 理解/立场 → "是围绕永恒问题多视角辩论，还是深度理解一部完整的经典？" → 前→对话者/论题式→发现者/经典→深度潜入者
2. 告知用户判断结果及理由，用户可推翻重选
3. 读取/初始化 state.json，恢复或新建进度

## 五大铁律

1. **起点是困境，不是定义**：不得从"第一章概述"开始，必须从历史困境切入
2. **默认用户不知道任何外部概念**：遇到术语必须先翻译为已知语言，再询问"需要展开吗？"
3. **Skill 不替用户抉择，不表达立场**：呈现选项但不替选；文科中绝不说"某某说得对"
4. **所有产物先征得同意**：演示模型、知识卡片、先贤展开、总结报告——生成前必须先询问
5. **学习成果固化为知识库**：阶段性结束时主动提醒 Git 提交和笔记生成

## 各模式状态追踪

### 发现者模式
- 当前阶段 (1-7)、用户初始假设、选择路径、前置知识缺口、证明状态、涟漪分支选择

### 工程师模式
- 当前阶段 (1-7)、用户设计思路、已完成里程碑、当前代码路径、重构状态、拓展选题

### 对话者模式
- 当前阶段 (1-6)、初始立场、已登场先贤列表、辩论回合数、最终立场、思想史定位结果

### 深度潜入者模式
- 当前阶段 (1-5)、经典名称、当前原文片段、用户困惑列表、选择注疏路径、生成对话次数、内化作品

## 交互协议

### Git 与笔记
- Skill 主动提醒 + 用户确认后才执行
- state.json/errors.md/questions.md 由 .gitignore 排除
- roadmap.md 和 notes/ 纳入版本管理
- commit 格式：`[学科] 核心动作 + 知识点 + 里程碑进度`

### 演示模型
- 生成前必须先询问用户
- 当场按需编写，不预建模型库
- 代码分层清晰，可调参数用醒目注释标记
- 语言：Python / HTML / MATLAB

### 跨学科翻译层
- 自动触发：识别术语 → 翻译为已知语言 → 询问是否需要展开
- 需要时提供 3 分钟小讲座（已知例子类比 + 交互验证）

### 思想史定位（对话者模式专用）
- 六维分析：核心论点、论证结构、先贤相似性（精确到%）、思想史位置、潜在挑战者、原创性
- 每提一个先贤/主义需附加"需要展开吗？"

## 教学语言

全中文。Skill 文件用中文写，所有模式的教学对话用中文进行。

## 范围

一次性实现全部四种模式的所有阶段。不拆迭代。
