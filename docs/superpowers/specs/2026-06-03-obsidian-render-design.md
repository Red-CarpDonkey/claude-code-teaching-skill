# Obsidian 实时渲染与知识卡片拆分设计

## 问题

当前 skill 在 CLI 中输出公式、图表、长推导，ASCII 无法直观呈现。使用报告显示 ASCII 图两次被拒，SAT 部分直接弃学。

## 目标

CLI 只做对话流。所有教学内容（LaTeX、mermaid、推导、代码、论证）实时写入 Obsidian vault，用户在 Obsidian 中查看渲染版本。分支选择点触发知识卡片拆分，建立双向链接网络。

## 设计

### 文件模型

```
[模式文件夹]/
  └── [主题]/                              # 每个学习主题一个子文件夹
      ├── [板书]-实时笔记.md               # 唯一黑板，未拆分内容
      ├── [知识点]-[名称A].md              # 已拆分知识卡片
      └── [知识点]-[名称B].md              # 已拆分知识卡片
00-总览仪表盘/
  └── 索引.md                            # 按模式分类，链接所有主题
```

- `[板书]-实时笔记.md`：追加式黑板。每次回复追加内容。分支点触发时，相关内容被剪切为知识卡片，原位置替换为 `→ 已拆分：[[知识点-名称]]`
- `[知识点]-[名称].md`：独立知识卡片，含 frontmatter、内容、双向链接
- `索引.md`：入口索引，按模式/主题分类，链接到所有卡片

### 输出路由规则

**CLI 只输出：**
- 提问（"你怎么看？""选哪条路？"）
- 简短引导（"推导已写入笔记，打开看看"）
- 确认/反馈

**写 Obsidian 的内容：**
- LaTeX 公式（`$$`）
- mermaid 图表（` ```mermaid`）
- 超过 3 行的推导过程
- 超过 5 行的代码块
- 超过 2 句的先贤原文引用
- 知识树/对比表/时间轴

**每次回复流程：**
1. CLI 简短对话文本
2. 教学内容写入当前 `[板书]-实时笔记.md`
3. 告知用户文件路径

### 分支点拆分

#### 拆分触发时机

| 模式 | 触发点 |
|------|--------|
| 发现者 | 阶段四选择路径、阶段五每步推导完成、阶段六选涟漪方向 |
| 工程师 | 阶段二设计取舍、阶段四变式挑战完成/代码评审通过、阶段六选拓展 |
| 对话者 | 阶段二初始立场、每位先贤辩论结束 |
| 深度潜入者 | 阶段三选注疏、阶段四每次对话回应、阶段五选创作形式 |

#### 拆分操作

1. 从 `[板书]-实时笔记.md` 剪切相关内容
2. 生成 `[知识点]-[名称].md`，含 frontmatter + 内容
3. 原位置替换为 `→ 已拆分：[[知识点-名称]]`
4. `previous` 指向前一张卡片，后续卡片生成时回填 `next`
5. 更新 `00-总览仪表盘/索引.md`

### 双向链接

每张知识卡片 frontmatter：
```yaml
---
tags: [模式, 主题, 子话题]
difficulty: 初|中|高
mode: [discoverer|engineer|dialoguer|deep_diver]
previous: "[[上一个知识点]]"
next: null
branch_of: "[[主题-学习总览]]"
---
```

链接关系：索引 → 主题总览 → 知识点链（previous/next）

### 工程师模式代码评审

用户提交代码作业 → 四维诊断：
1. 语法问题：具体位置 + 修正
2. 逻辑问题：为什么不对 + 正确思路
3. 语言规范：命名、const、RAII、所有权、惯用法
4. 设计改进：扩展性考量

诊断写 Obisidian 不在 CLI 刷屏。通过后触发拆分 → 生成 `[知识点]-[代码评审-题目].md`。

### 挖坑与递进原则

#### 挖坑三步

1. **预设陷阱**：在提问或代码框架中刻意埋入典型错误
2. **让坑暴露**：不立即纠正，让后果自然展开
3. **爬坑即学会**：揭示历史上真实发生过的同样错误

#### 由浅入深

1. **最小可行理解**：最简单情况，先跑通
2. **用户撞边界**：给出超出简单模型的输入
3. **引入复杂性**：简单模型不够用时自然引出完整模型

禁止一次给完整定义——完整定义是终点，不是起点。
